## Package/hop chosen and why (not openai)

**Hop:** `pydantic` PyPI `*` → `2.0.0` (consumer pin observed: `1.10.13`).

**Why this hop (not openai / ChatCompletion):**

- Same package name, so Watch pin matching and `DEPENDENCY_BUMP` can actually run on a real manifest (PEP 621 `pyproject.toml`).
- Official migrate guides exist and were fetchable:
  - https://docs.pydantic.dev/latest/migration/ (fetched body length 198498)
  - https://docs.pydantic.dev/2.0/migration/ (fetched body length 174942)
- A **current HEAD** public consumer still on v1 APIs: [`pedrolabonia/pydavinci`](https://github.com/pedrolabonia/pydavinci) (`pydantic==1.10.13`, `@validator`, `.dict()`, `BaseModel`).
- Not the openai 0.28 `ChatCompletion.create` demo hop.

**Not chosen:** `google-generativeai` → `google-genai`. README’s producer example is the successor package `google-genai`. Without LLM enrichment, `packet new` still only emits `DEPENDENCY_BUMP` for `google-genai`, so Watch against a `google-generativeai` consumer would `no_pin` (exit 2). Pydantic lets the consumer path run instead of dying on package-rename mismatch.

Checked-in `packets/google-genai-pypi-1.0.0.json` on main is the same shape (one `DEPENDENCY_BUMP`, no AST rules).

## Gaps vs design (watch / publish / apply)

Design (locked): packets are a notable hop; **apply kill bar** = mergeable transform on a real upgrade path; Watch fails CI when the pin reached `to_version` but call sites are not packet-clean; producer CLI = catalog publish only.

| Surface | What worked | Gap vs design |
|---------|-------------|----------------|
| **packet new / publish** | Flags exist; schema-valid packet; temp catalog `by-package/<pkg>/<eco>/<id>.json` written; no consumer PR fan-out. | Without LLM, hop is **pin-only**. Migrate-guide HTML was fetchable but unused for AST rules. Cannot mint a pydantic (or google-genai) call-site packet on this environment. |
| **Watch** | Reads pin from PEP 621; exit 0 pre-bump; exit 0 post-bump. | Leftovers only come from packet `old_callee` / export-delta gone symbols. Pin-only packet ⇒ **zero leftovers** even with `@validator` / `.dict()` still in tree. After bump, Watch is **clean** — the opposite of “fail until call sites match the hop.” `from_version: *` never matches the consumer pin as “from.” |
| **Apply / run** | Rewrites PEP 621 pin; `--skip-pr --skip-tests` exercise apply without a PR. | Not mergeable. Kill bar missed. `run` reports **PASSED**. Export-delta cannot resolve `from_version=*`. Coverage scores 0 client tokens so it cannot flag misses. Dry-run still writes `.gitignore`. Verify-venv pip install skipped (interpreter path check). |
| **modules/detect** | Not used as the hero path (explicit `--packet` file). | n/a for this smoke; detect still in the CLI (`conduit detect` / `module`). |

## Verdict

**partial** for non-openai real-repo use.

- **Not ready:** apply does not produce a mergeable pydantic v1→v2 change; Watch cannot see v1 leftovers from a `packet new` artifact; `run --skip-tests` is a false PASSED.
- **Not fully broken:** producer new/test/publish and consumer watch/apply/run all **exit 0** against a real public repo and a real non-openai package; catalog layout is written.

Blocking product gap for a second SDK: **AST/import rules are LLM-gated.** On a machine with no LLM, every non-openai `packet new` hop is a version bump. Watch then treats “pin reached `to_version`” as clean.
